智慧餐厅机器人（竞赛）

# 智慧餐厅机器人（竞赛）

# 项目描述

全国智能汽车竞赛-智慧餐厅组别：开发基于 ROS 和 AI 算法的智能移动机器人，在以地形和障碍物模拟室内餐厅环境的场景中，该机器人能较好地完成定位导航、人脸识别、自动导航和语音控制与播报等任务。

# 主要工作

  1. 上位机 (Jetson Nano) 中以 ROS 中 move_base 导航栈进行路径规划与实时避障算法的设计。
  2. 下位机（STM32F407）中重新编写运动控制算法，确保麦轮小车的精确运动控制。
  3. 基于 YOLO 算法采集、训练数据集，实现人脸识别功能，在讯飞 SDK 基础上二次开发实现语音 识别与播报功能。
  4. 多传感器（IMU、雷达、里程计）融合定位 (室内，±3cm) 的实现，最后在狭窄场景 (4x4m, 最小通行宽度 <50cm) 完成了所有任务。

# 成果

成功完成所有任务，校赛(第一名) -> 线上赛(纯成绩第二名，综合第六名) -> 区赛(第二名) -> 全国总决赛(一等奖,第四名)

# 项目实施过程

通过对比并决定了最终的方案设计之后，就进入到了方案的实现环节。具体的实施过程包括对数据的采集和处理、各种分析工具的使用和对比，同时，也遇到了一些问题，通过多次的尝试和不断的测试，在解决一个个问题的基础之上完成了整个方案的优化和实现。

# 数据采集和处理

# 激光雷达

对于运动中的机器人来说，对周围障碍物的位置的识别，空间的轮廓信息的获取是非常重要的，同时，这对于机器人创建地图一个导航定位来说，也是不可或缺的。而通过激光雷达获取这些信息自然是不二之选，从而测量机器人和周围环境的距离，并通过LaserScan的话题类型发布数据。如图4.1所示。

# 里程计

里程计通过传感器收集数据来估计机器人在里程计坐标系中的随着时间变化的位置，常见的里程计有激光里程计，轮式里程计等等。但是这些里程计都会随着时间产生累计误差。需要ekf（扩展卡尔曼滤波）以及amcl（自适应的蒙特卡洛定位法）定位并纠正误差。而本次仿真使用的是由gazebo插件提供的里程计，基于直接读取在gazebo仿真世界中的坐标进行定位，理论上来说不存在误差，因此用作机器人的定位非常精准，也因此放弃使用ekf融合数据，但保留amcl用以发布map坐标系到odom坐标系的tf转换。如图4.2所示。

# TF变换

在仿真世界中，机器人各个组件之间、机器人本身与外界环境之间的相对位置关系是通过坐标变换实现的。在本次方案设计中，涉及到坐标变换的，主要有机器人本身的xacro模型文件中的坐标系，以及odom里程计坐标系和map世界坐标系。其中，机器人各个组件的坐标变换由robot_state_publisher节点发布；odom坐标系由gazebo插件发布;map坐标系由amcl发布。这样，整个仿真的tf变换关系就搭建完成了，如图4.3和4.4所示。

# 分析工具的使用

# rqt_graph（数据绘图工具）

rqt_graph是可以将当前ROS系统中的计算图通过图形化的方式展示出来的工具。在使用时，可以直观的展示所有启动的节点和话题，并将各节点之间消息流清晰的展示出来。如图4.5所示。

# rqt_reconfigure(参数动态配置工具)

rqt_reconfigure是可以在不重新启动仿真的情况下情况下，进行参数的动态配置的工具。在本次设计中，对于数量较多的参数，类似move_base功能包的参数，尤其是teb_local_planner相关参数，使用此工具进行配置十分便捷。如图4.6所示。

# rqt_tf_tree（tf变换查看工具）

rqt_tf_tree可以通过命令查看当前仿真中建立的tf坐标变换，直观而简洁地展示整个仿真世界中的坐标系之间的关系。

# 建图

建图采用的算法是gmapping算法，在场景较小时，可以在室内建图的过程中保持较高的精度。本次线上赛的地图较小，采用gmapping算法可以节约资源，同时可以得到不错的建图效果。

  • gmapping的配置 主要是通过launch文件完成的，以下是gmapping算法的部分配置参数和运行的结构，如图4.7及4.8所示。

# 导航

本次设计导航依靠的主要功能包是move_base，其中全局路径规划和实施路径规划采用global planner和local planer，运动控制采用teb local planner的参数调节和自己编写的控制算法结合的方式。

路径的算法采用Dijkstra算法，作为一种广度优先的算法，在这种地图不大，不需要太多的计算资源的仿真中无疑更有优势。在本次设计中，global planner规划出一条全局路径，而local planner 规划的局部路径在考虑实时避障的情况下尽量逼近全局路径。如图4.9所示。

# 控制算法

机器人控制方面主要从三方面进行了考虑：

  1. teb local planner：作为路径规划算法，teb也提供了大量的参数对机器人的速度、避障等方面进行调节，因此，要想控制好机器人的控制，是离不开对这些参数的优化的。
  2. skid_steer_drive_controller：本次线上比赛使用的机器人是四轮差速驱动的，而gazebo控制插件也并非常用的gazebo_ros_control，而是一个四轮驱动插件skid_steer_drive_controller，因此，要想控制好机器人，尤其是控制转弯，了解该插件控制四轮差速机器人的原理就变得非常重要了。

  1. 自编写控制算法：为了提升速度，需要对控制算法进行优化，其中最直接的就是直道加速，弯道减速了。而实现这种效果的方法很多，最后采取的方法是：通过选取机器人移动时前方一段路程的三个点作外接圆，其半径作为曲率半径，当前方一段路程的最小曲率半径达到某个值时，机器人就减速。由此实现在全图灵活的控制速度。

# 所遇到的困难及解决的方法

困难：

  1. 在使用gmapping算法之前，尝试使用cartographer建图，但偶尔会出现地图漂移重合的问题
  2. 运动控制时，机器人转弯速度不够快，且由于小车惯性较大，容易出现转弯和最后结束的时候刹不住车的问题。 解决方法：
  3. 在cartoprapher的lua文件中可以选择使用里程计和imu，从而增加定位精度，同时在建图过程中使机器人低速移动以得到准确度更高的地图。后面与gmapping的地图对比发现差异不大，不过为了建图的稳定，小组成员最后还是选用了gmapping算法。
  4. 编写直道加速，弯道减速的控制程序，以达到灵活转弯的效果，在最后停车时，通过终点前减速来平稳停车。

# 项目数据分析

对于仿真比赛所指定的实现自主导航及避障的任务，在完成上层算法设计和落地实现后，需要对算法进行修正优化。为此，小组成员通过多次实验测试来获得仿真数据，对结果进行测试对比，针对仿真结果多次修改参数以得到较好的仿真数据。因此本章的测试结果均由优化前和优化后的对比得出结论，进而根据实验效果进行相应改进。

# 数据来源及处理

根据比赛要求，根据完成全程导航所需时间和途中与障碍物和墙壁的碰撞情况来评定成绩，便基于此将导航数据中的全程时间和碰撞次数作为评价指标来比较实验效果。

对于全程时间，分别记录车辆出发时和到达终点时的ros_time_now()，做差值后进行发布，即所要求的全程行驶的总时间。对于碰撞次数，打开Rviz中的camera，通过其镜头上下抖动次数和Gazebo中小车经过障碍物后发生明显偏移的情况来得到小车碰撞次数。此外，在仿真赛道中的不同位置加入不同数量的桶锥来构建多个难度等级的world模型，通过上述两个评价指标来判断小车速度规划好坏和避障能力。对每个地图多次修改Teb参数，使得上述两个指标达到最好目标为止，一共得到千余组数据。

Teb_local_planner的参数修改，修改部分主要分为小车自身尺寸运动参数、从全局地图获取信息的参数、误差参数、以及规划时对于各种要求的权重参数，对于各个路况都有一个甚至几个参数的调试能够改善此种路况的行驶性能，在此过程中花费了大量时间处理各种路况下的较优参数并整合成一套比较全面的参数，能够解决绝大部分的路况行驶。

# 停车测试

能够平稳而快速的停车是提高小车在整个流程的速度的最直接的方法之一，为了达到此目的，本设计采用了终点前一段距离刹车，依靠惯性停车，并在离设定终点最远，但又在终点允许区间内的坐标停车。以下为数据统计结果，反应了最终效果良好。

# 速度测试

  • 仅调试teb参数，无其它控制算法 配置好工作空间后，进行第一次调试。系统节点如图5.5所示。

完整跑到终点的速度为1.66m/s，耗时48.25s。

对teb_local_planner中的参数进行修改，发现很多参数会对小车产生影响，但是有的参数数值需要改动很大才能看到效果，有的参数改动0.1就可以产生很大效果。比如max_vel_x参数，仿真时设置为1.0，如果改为0.9，就会转不过弯。 经过调试，发现修改以下参数（如图5.6所示）会对运动控制造成显著影响。

由于车模较重，速度和角速度不能同时增大太多，否则会出现过弯冲出路线的情况，因此车速有上限。

最终单纯调试teb参数的结果为41s左右，并不理想。

  • 增加简单的加速控制（以角度为条件） 为解决弯道速度太快撞墙的问题，小组成员采取了分段控制加速的方法，转向角度较大时，速度增益为小于1的值；转向角度较小时，速度增益为大于1的值。详细代码如图5.8所示。

根据不同角度值调节速度增益，最终所用时间达到32s左右。

  • 增加曲率探测 由于赛道存在较多弯道，且道路较窄，通过角度控制增益并不能得到非常理想的效果，因此小组成员决定采用曲率探测的方法，提高小车的前瞻性，从而减少弯道过度减速的影响，可以更细节的控制加减速。 通过更改三个前瞻点之间的距离和第一个前瞻点到小车的距离来测试曲率探测的效果。距离如图5.9所示。

a. 小车在右上角弯道撞墙，无法完成赛道。 b. 完赛时间29.00，小车速度2.76m/s。

c.完赛时间28.25，小车速度2.83m/s。效果最好。

综合以上结果，最终完赛时间为28s左右。

  • 获取到目标点的距离 由于地图是固定的，小车到达每个路段时到终点的距离是相同的，因此决定采取以距离为判断依据的分段加速方法。 小组成员在不同路段设置了不同的速度增益和角速度增益下，通过调试，进行增益的修改，从而使小车速度达到最理想的状态。 最终完赛时间到达24s左右。

# 分析与结论

通过对仿真结果的分析，对TEB参数进行多次修改，由于TEB是软约束，所以测试效果具有随机性，为了保证调整后的参数具有较强的鲁棒性，每套参数组内都测试4次以上。在调试过程中发现小车会出现拐不过弯，容易撞墙的现象，为此小组成员调小了膨胀距离等参数。

通过对结果的分析，发现局部规划路径对于全局路径依赖性较强，同时车辆的横向控制仍有提升空间，因为大多数时候是后轮轻擦锥桶，同时由于TEB是软约束，不能保证每次测试结果都大致相似，测试的效果与测量的目标点的选取有一定的关系，选择一个较好的目标终点有助于提升测试成绩。
